## 1.1.2 确认窗口中文编码修复

验证日期：2026-10-04（Asia/Hong_Kong）。

- 用户截图确认 1.1.1 独立窗口已能显示，正文中文正确、标题和按钮乱码；取消返回 written=false，没有写入。
- 原因是 Windows PowerShell 5.1 默认按系统 ANSI 编码解析无 BOM 的脚本，脚本中直接写入的中文标签会损坏；stdin JSON 的 UTF-8 编码不受影响。
- Windows 辅助脚本改为 ASCII 源码，三个中文标签按 Unicode 码位生成，避免打包平台改变 BOM 导致乱码。
- 新增回归测试：检查脚本 ASCII 字节；使用实际 Windows PowerShell 5.1 文件解析器读取脚本，并只运行三个标签表达式，确认标题为“思源笔记 · 写入确认”、按钮为“确认写入”和“取消”。不打开 GUI，不读取用户配置或 Token。
- 42 项自动化测试：41 项通过，0 项失败，1 项 DPAPI 测试因沙箱配置限制跳过。新标签的真实窗口显示仍待更新后验证。
- 本次未增加图片上传：归档仍保留用户与助手文字、已有 Markdown 链接和附件说明，不复制图片文件到思源资源库。

## 显示限制与待验证事项

此前代理沙箱后台启动的 GUI 对用户不可见；改变隐藏标记后，沙箱启动的窗口仍不可见。1.0.1 增加模型可见配置工具，要求直接由本地 MCP 插件进程打开窗口，并使用可见交互启动及显式恢复窗体。不得以进程启动成功代替用户看到窗口的验证。

受限测试进程无法使用当前桌面用户的 DPAPI，保护往返测试跳过；已安装插件的真实鉴权成功验证了已保存 Token 可由实际插件进程读取并用于鉴权。新版本安装后的原生弹窗显示仍需在桌面宿主更新或重新加载后实测。Windows 可以限制前台激活，前台请求不是显示成功的保证；不支持交互桌面的宿主仍应由用户手动双击 `Configure.cmd`。
