# 知识地图工作流

版本 1.3.0 新增 7 个工具，服务总计 26 个工具。原有连接配置、聊天文字与图片归档、确认窗口与单篇写入保持兼容。

| 工具 | 用途 | 思源副作用 |
| --- | --- | --- |
| siyuan_list_documents | 固定分页清单、引用数量 | 无 |
| siyuan_list_references | 块或整篇文档的入链、出链 | 无 |
| siyuan_start_knowledge_job | 指定笔记本全库清单，最多一万篇 | 无；仅存本机任务 |
| siyuan_read_knowledge_job | 读取任务清单、分层阶段与写入日志 | 无 |
| siyuan_read_knowledge_source | 带块 ID 的完整 Kramdown 分页 | 无；本机记录页段和 hash |
| siyuan_record_knowledge_analysis | 记录主题、摘要、原文证据 | 无；本机记录模型分析 |
| siyuan_prepare_document_batch | 同一笔记本批量新文档预览 | 无；提交后用户确认才创建 |

任务存于插件现有配置目录下 `knowledge-jobs/<jobId>.json`，不能由工具指定任意路径；不保存 Token 或全文快照，但会保存私人的文档清单、模型摘要、证据片段和写入状态。只在本机使用，不应打包或提交到 GitHub。任务绑定原有连接，连接变化时停止使用。建议记录 jobId 以便重启后续做。

读取以全文 hash 和已返回的页段追踪覆盖，跳过开头或中间不能记为完成。sourceHash 变化后重新读取会清除旧分析。记录分析时重新读取当前文档，验证 hash，并核对证据块属于该文档及逐字片段。该检查证明片段有出处，不能证明模型归纳的因果关系，也不是外部事实核验。

批量新建上限为 50 篇、总正文 500000 字符、单篇 100000 字符。预览列出每篇目标、hash 和全文，沿用默认原生确认与单次操作 ID。拒绝、过期、取消、连接变化或既有路径停止写入。确认后再次检查全部目标，写入前逐项检查。与外部并发编辑并不构成原子锁，仍需回读路径。

批次逐篇创建，不是事务，不回滚。关联 jobId 时，在请求发出之前持久记录 attempted；响应中断或进程崩溃后必须先核对目标。创建后读取真实路径与源码 hash；created_readback 只代表已取得源码，仍须检查内容。日志区分未开始、已创建、已回读、回读失败与不确定结果，绝不自动重试未知写入。

引用数量使用思源公开 SQL API 的固定 SELECT 与 refs 表。表结构参考 [官方数据库源码](https://github.com/siyuan-note/siyuan/blob/master/kernel/sql/database.go)；创建、路径查询和源码读取参考 [官方 API](https://github.com/siyuan-note/siyuan/blob/master/docs/API.zh-CN.md)。只读列表来自当前索引，可能滞后；普通 Markdown 导出也可能展开引用，原文分析和结构核对使用 Kramdown。

知识地图的语义工作由当前对话中的模型执行：盘点 → 主题试点 → 规则与证据 → 分批扩展 → 问题验证。插件不含模型 API 密钥、任意 SQL、后台扫描、自动向量模型或删除功能。全库抓取和词项索引不应声称为全库精读；虚构小说、摘录、AI 回答、个人观点及历史事件分别保留来源身份。

在真实笔记库操作之前，应先运行包内测试，并按技能用少量文档验证连接、全文分页、引用查询与用户确认。测试不会替用户批准真实写入。
